## Active-workout overview

**Q1 — Landing anchor on the overview.** When you open/resume a workout, should the
overview scroll to the **active set** (fast path for someone mid-exercise) or to the
**top of the list** (pure Hevy)?
- *Recommendation:* anchor to the active set but render the full scrollable list around it — keeps the one-tap loop and the at-a-glance overview.

**Q2 — Is the overview the only active-workout screen, or is there still a per-exercise focus view?**
- *Recommendation:* overview-only (Hevy/Strong model); drop the dedicated single-exercise focus screen to avoid two navigation models. If you value the current focused view for gym-floor readability, we keep it as an optional drill-in. Default: overview-only.

**Q3 — Empty workouts.** Today "empty workout" is a distinct state. Under the overview,
should starting empty just be "an overview with zero exercises and a prominent Add
exercise button" (Hevy's build-as-you-go)?
- *Recommendation:* yes — unify empty workout into the overview; it makes Add exercise the natural first action.

## Add / replace / remove

**Q4 — Add exercise: single or multi-select** from the library picker in one go?
- *Recommendation:* single for v1.1 (simplest, matches the current picker); multi-select is an easy fast-follow if you want it.

**Q5 — Where does an added exercise land** — always end of session, or insertable at a chosen position?
- *Recommendation:* append to end for v1.1 (then reorder if desired). Positional insert adds picker complexity for little gain.

**Q6 — Replace with completed sets present.** My proposed rule keeps the original as
**skipped** and appends the replacement (history-safe). Alternative: block replace once any
set is completed and tell the user to add + skip manually.
- *Recommendation:* keep-skipped-and-append (smoother, still fully history-safe). Confirm you're OK that a replaced-but-partially-done exercise remains visible as skipped in history.

**Q7 — Added/replacement exercises and progression.** An added exercise has no plan-target
lineage, so it gets **manual targets and no auto-progression recommendation**. OK? (The
alternative — retro-fitting it into progression — conflicts with "no silent target
changes.")
- *Recommendation:* manual-only for added/replacement exercises in v1.1.

## Scheduling / history semantics

**Q8 — Does mid-workout editing count as completing the scheduled day?** Proposed: yes —
the scheduled opportunity is consumed (you trained), but the session is flagged
**modified-from-plan**; rotation/weekday advancement still occurs on commit.
- *Recommendation:* consume the opportunity + flag modified-from-plan. Confirm you don't want edited sessions to *not* advance the schedule.

**Q9 — Do mid-workout edits ever write back to the plan?** i.e. if you add an exercise
during Monday's workout, should Monday's *plan day* offer to keep it next week?
- *Recommendation:* NO for v1.1 — session edits stay session-scoped; plan editing remains a separate explicit action. A "save these changes to the plan?" prompt is a good v1.2 idea but out of scope here.
