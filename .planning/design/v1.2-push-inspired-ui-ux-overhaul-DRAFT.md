## Reference Basis

Research was performed against these public sources on 2026-10-01:

- `https://www.pushapp.co.uk/`
- Apple App Store listing for `PUSH Workout & Gym Tracker`, app ID `1621689462`,
  version `4.0.4`
- The eight current App Store product screenshots
- Gym Tracker's shipped v1.1 screens, shared components, theme, and design system
- The approved Gym Tracker core-workout and app-system references

The target is a localized interpretation of PUSH's interaction economy:

- large workout identity before controls
- low-chrome, dark-first visual hierarchy
- one obvious completion action
- compact, table-like set rows
- state color used only for current, completed, attention, and error states
- progressive disclosure for advanced actions
- one meaningful progress visual at a time

The target is not a pixel-for-pixel clone. Gym Tracker keeps its own identity,
fonts, content, Android behavior, offline-first architecture, accessibility
contract, and evidence-backed progression rules.

## Why This Phase Exists

The current product is behaviorally complete but visually exposes too much of its
implementation structure:

- Today wraps the workout and every exercise in separate content cards.
- Active Workout presents a generic `Workout` header, repeated section headers,
  nested-looking bounded regions, and a large number of visible secondary actions.
- Warm-ups, advanced timing, working sets, editing, reordering, and recovery all
  compete in the same scroll hierarchy.
- Progress explains every source and state inline, so evidence competes with the
  result the user came to see.
- Repeated border, card, and button treatments make safe actions, primary actions,
  navigation, and disclosure feel equally important.

The result is trustworthy but slow to scan on the gym floor. This phase makes the
same capabilities feel immediate, calm, and one-handed.

## Goal

Rebuild the presentation and interaction layer so the owner can open the app,
understand the current workout in three seconds, complete a set with one obvious
action, and reach secondary controls without those controls dominating the screen.

## User Journey and Emotional Arc

| Moment | Owner does | Intended feeling | Design response |
|---|---|---|---|
| Open at the gym | Launches the app, often one-handed | Oriented, not briefed | Workout identity and Start/Resume appear before explanation |
| Scan the session | Checks exercises and targets | Prepared | One grouped workout preview; no card-per-exercise maze |
| Perform a set | Confirms or edits values | Focused | Current set is the only visually active row |
| Commit the set | Taps completion | Certain | Commit-gated state change, haptic, green confirmation, Undo |
| Rest | Glances at the phone between sets | Unburdened | Timer and four controls replace the completion action in the same dock |
| Handle an exception | Replaces, reorders, corrects, or configures timing | In control | Contextual sheets preserve the primary workout hierarchy |
| Recover | Returns after backgrounding or process death | Reassured | Exact exercise, set, values, and rest state reappear with concise recovery copy |
| Finish | Reviews the session and any target decision | Accomplished, not judged | Factual summary, one next action, evidence available on demand |

Time-horizon target:

- **First 5 seconds:** the current workout and next action are unmistakable.
- **First 5 minutes:** editing, completion, and rest feel predictable without
  reading instructions.
- **Long-term:** history, recommendations, backup, and recovery continue to feel
  trustworthy because the redesign never hides source facts or changes them
  implicitly.

## Locked Carry-Forward Contracts

This phase must not weaken any shipped behavior:

1. SQLite source facts remain authoritative.
2. A set is never acknowledged before its exclusive transaction commits.
3. Notifications, projections, recommendations, and UI caches remain rebuildable.
4. The workout critical path remains fully offline.
5. Existing metric profiles, schedule rules, advanced timing, editing, undo,
   correction, partial completion, and recovery behavior remain intact.
6. Recommendations remain evidence-backed and require explicit acceptance.
7. System, Light, and Dark appearances remain supported. The PUSH reference is
   dark-first, not dark-only.
8. Touch targets remain at least 48dp, required actions remain reachable at 200%
   text, and keyboard/D-pad alternatives remain available.
9. Existing p95 interaction and launch budgets remain release gates.
10. The signed personal-use Android delivery model remains unchanged.

## Reference Translation Matrix

| PUSH pattern observed | Gym Tracker adoption | Localization rule |
|---|---|---|
| Large horizontal `Day 1 / Day 2 / Day 3` selector | Compact workout-day switcher above the scheduled workout | Use real plan-day names and schedule semantics; changing the preview does not silently advance rotation |
| Workout preview as one grouped list | One workout surface containing exercise rows | Show exact next target and comparable-history cue without one card per exercise |
| Set table with number, load, reps, and one check action | Shared inline `SetRow` rebuilt as a dense state row | Preserve all nine metric profiles and commit-gated completion |
| Yellow active/achievement row and green completed row | Semantic active/attention and committed-completion states | Pair color with set number, icon, label, and accessibility state |
| Add-set menu for regular/drop/myo set types | Context menu for supported set and timing actions | Do not invent unsupported drop-set or myo-rep domain facts |
| Sheet-based workout and exercise actions | Bottom sheets for edit, add, replace, reorder, timing, and outcome actions | Keep destructive confirmation and focus restoration |
| One large progress chart followed by related rows | One primary trend per view, then concise evidence rows | Use existing factual projections; no global fitness score or fake volume metric |
| Muscle anatomy heat map | Not copied in this phase | No anatomy asset or muscle-volume model exists in Gym Tracker's current authority |
| Black canvas, muted grey surfaces, white primary action | Dark-first neutral hierarchy with an equivalent light theme | Use Gym Tracker tokens and fonts; do not copy PUSH brand assets |
| Watch and Live Activity surfaces | Not in scope | Android phone remains the delivery target |

## Proposed Information Architecture

```text
Root shell
├── Workout (rename of Today)
│   ├── Day switcher
│   ├── Scheduled/rest/active workout identity
│   ├── Exercise preview with next targets
│   └── Start or Resume
├── Calendar
│   ├── Month
│   └── Selected-day session list
├── Library
│   ├── Plans
│   └── Exercises
├── Progress
│   ├── Period summary and primary trend
│   ├── Needs review
│   └── Exercise trends
└── Settings
    └── Opened from Workout header, never a root tab

Focused workout route
├── Workout identity and exercise progress
├── Exercise sections
│   ├── Exercise header and overflow
│   ├── Optional warm-up disclosure
│   ├── Working-set table
│   └── Advanced timing disclosure
└── Sticky dock
    ├── Complete current set
    ├── Rest controls
    ├── Save failure / Retry
    └── Finish workout
```

The four-destination architecture stays. The proposed label change from `Today`
to `Workout` is a review item, not a locked decision.

## Screen Contracts

### 1. Workout Root

First, second, third:

1. Current day/workout identity and state.
2. Primary action: Start or Resume.
3. Exercise preview and secondary day choice.

Contract:

- Replace the generic `Today` composition with a workout-first header.
- Show the current plan's days as a horizontally scrollable selector only when
  more than one day is available.
- Keep the scheduled day selected on entry. Previewing another day is reversible
  and does not mutate the schedule.
- Present the workout as one grouped surface. Each exercise row shows name,
  planned sets/reps or profile summary, next target, and one short history cue.
- Keep Start or Resume visible before the exercise list can scroll it away.
- Move alternate-day, empty-workout, and schedule details into one start sheet.
- Rest day uses the same shell with the next scheduled workout visible and
  `Train anyway` as the single primary action.
- Active and saved-partial sessions replace the scheduled preview with a compact
  resume surface; do not show both Start and Resume choices.

### 2. Active Workout

First, second, third:

1. Current exercise and current set target.
2. Working-set table and single completion action.
3. Warm-ups, advanced timing, editing, and workout management.

Contract:

- Replace the generic `WORKOUT OVERVIEW / Workout` header with the workout name,
  elapsed time, exercise position, and compact progress.
- The active exercise expands automatically. Completed prior exercises collapse
  to one row. Future exercises show one-row previews until opened.
- Exercise name and current target remain visible while its sets are on screen.
- Working sets use one table-like surface, not a card plus a separate card for
  each state. Columns adapt by metric profile.
- The active set uses a clear state band and a visible set number. Completed sets
  use committed-green plus check icon. Planned sets stay neutral.
- The row completion affordance invokes the same command as the sticky dock; it
  does not introduce a second mutation path.
- The sticky dock always owns the dominant action:
  - `Complete set N`
  - rest countdown and four rest controls
  - `Set not saved · Retry`
  - `Finish workout`
- Warm-ups begin collapsed after completion. Adding/removing them lives in the
  warm-up disclosure, not beside the primary workout action.
- Advanced timing shows a compact status row. Full configuration opens a sheet.
- Add/replace/remove/reorder, finish partial, and discard remain available from
  exercise or workout overflow sheets.
- Completed-set correction remains reachable from the completed row and retains
  revision checks and audit behavior.
- Long exercise names wrap to two lines; the active exercise never truncates to
  an ambiguous label.

### 3. Progress

First, second, third:

1. Selected period and one plain-language outcome.
2. One primary trend visual with its current value.
3. Needs-review and exercise rows.

Contract:

- Retain `4 weeks / 12 weeks / All time` in a compact segmented control.
- Lead with one primary consistency or exercise trend, never a mosaic of metric
  cards.
- Show source/evidence details on demand in a sheet or detail route instead of
  repeating source buttons under every sentence.
- Keep pending target recommendations visible and explicit, but shorten the
  landing view to exercise, current target, proposed target, and review action.
- Keep accepted/rejected review history behind a disclosure.
- Exercise rows show name, latest comparable result, trend state, and last date.
- Keep accessible text and data-table equivalents for every chart.
- Do not add a muscle heat map, readiness score, recovery score, or aggregate
  kilogram-volume headline without a separately reviewed data contract.

### 4. Calendar

- Keep the month grid and selected-date facts.
- Reduce chrome around month navigation and day states.
- Use one continuous calendar surface with clear selected/today/completed/partial
  states rather than independent day cards.
- Selected-date sessions become grouped rows with one-line progress and status.
- Session correction/removal remains in the session route, not on the month grid.

### 5. Library

- Keep the `Plans / Exercises` segmented switch and the saved last-opened section.
- Use one search/filter strip, followed by grouped flat rows.
- Active plan, owned plans, starter plans, favorites, recent, and all exercises
  use editorial section boundaries. Use cards only when the whole row is the
  selection target.
- Create, filter, sort, and import actions move into a single contextual header
  or sheet so they do not all compete at once.
- Preserve queries, filters, and scroll position when moving into a detail route.

### 6. Settings and Detail Screens

- Use grouped navigation rows on one continuous canvas.
- Keep appearance, rest alerts, timing defaults, history/data, and recovery as
  clear sections.
- Keep destructive or privacy-sensitive actions in dedicated detail routes with
  explicit confirmation.
- Normalize headers, sheets, input rows, empty states, and action hierarchy to
  the new system; do not redesign storage or backup behavior in this phase.

## Design System Delta

The existing `DESIGN.md` remains the base. This phase proposes these amendments:

### Typography

| Role | Proposed treatment |
|---|---|
| Workout/display title | Source Sans 3 SemiBold, 32-36sp, compact line height |
| Screen title | Source Sans 3 SemiBold, 28-32sp |
| Exercise title | Source Sans 3 SemiBold, 18-20sp |

### Color

Dark is the primary design reference, while System/Light/Dark behavior remains:

| Semantic role | Dark proposal | Light proposal | Use |
|---|---:|---:|---|
| Canvas | `#080808` | `#F4F4F2` | Continuous root background |
| Raised group | `#151515` | `#FFFFFF` | Workout group, sheet, grouped rows |
| Active row | `#3A3210` | `#FFF3B8` | Current set or owner attention |
| Completed row | `#12351F` | `#DDF7E7` | Committed completion only |
| Primary text | `#F5F5F5` | `#141414` | Main copy |
| Secondary text | `#9C9C9C` | `#626262` | Supporting copy |
| Primary action | `#F5F5F5` | `#141414` | One dominant action per section |
| On primary action | `#090909` | `#FFFFFF` | Action label/icon |
| Progress accent | `#2F9BFF` | `#006EDC` | Selected trend and progress data only |
| Completed | `#32D66B` | `#168A45` | Committed set/session state |
| Attention | `#FFD21C` | `#9A6A00` | Current target/attention, paired with text |
| Destructive | `#FF5C5C` | `#B42318` | Error/destructive only |

The current cobalt action token is not used as general decoration. The exact
values remain subject to contrast measurement and visual review.

### Shape and Surface

- 16-20dp radius is reserved for large grouped workout or sheet surfaces.
- 10-12dp radius is used for rows and controls.
- Full-round is limited to circular icon actions and compact segmented/filter
  controls.
- Grouped surfaces use spacing and one outer boundary; internal rows use
  dividers or state fills rather than nested cards.
- Shadows are optional and subtle. Hierarchy must survive with all shadows off.

### Iconography and Motion

- Continue Lucide React Native with 2dp strokes.
- Circular icon buttons remain 48dp minimum.
- Set completion: 140ms state fill plus existing haptic after commit.
- Exercise collapse/expand: 180-220ms height/opacity transition.
- Sheet: platform translation/fade; reduced motion uses fade only.
- No bounce, decorative parallax, or animated charts from zero.

## Responsive and Accessibility Contract

- Compact `<600dp`: bottom navigation, single-column content, sticky dock.
- Medium `600-839dp`: centered primary column; optional secondary context below
  or beside only when reading order stays clear.
- Expanded `>=840dp`: navigation rail permitted; workout action and set table
  remain together within the 720dp active-work width.
- At 200% text, actions grow vertically, day labels wrap or use a sheet, set
  columns stack into labelled value groups, and the sticky dock stays reachable.
- Every state color has text, icon, shape, or selected semantics.
- Every icon-only action has an exact accessible label.
- Focus order follows the visual order; sheets trap and restore focus.
- Reordering retains non-gesture alternatives.
- The active set completion custom action continues to invoke the same
  transaction as touch.
- Charts retain text summaries and accessible data tables.

## Success Criteria

1. The owner can name the current workout, exercise, set, and next action after a
   three-second scan of the relevant screen.
2. The scheduled workout starts within two unambiguous taps.
3. A normal working set completes with one dominant tap and no competing primary
   action.
4. The active set, rest state, and save failure stay visible without searching
   through secondary controls.
5. Advanced actions remain discoverable within one contextual sheet from their
   owning workout or exercise.
6. Root and workout screens contain no decorative nested-card hierarchy.
7. System, Light, Dark, 200% text, landscape, keyboard/D-pad, and non-color state
   cues pass the defined evidence matrix.
8. No domain, persistence, recovery, recommendation, backup, or sync contract
   regresses.
9. Existing performance budgets remain within tolerance.
10. The owner approves the installed-device experience before release.
