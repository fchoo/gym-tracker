<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm/Maven/GitHub release → repository | Third-party packages, templates, actions, and Maestro assets enter the build. |
| committed CNG config → generated Android | Disposable native output must reflect only reviewed committed configuration. |
| Android backup service → local app data | OS backup/transfer must not copy authoritative SQLite or sensitive staging files. |
| development-test artifact → installed device | Test-only routes and diagnostics may exist only in the private development-test variant. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | package-lock.json and downloaded tools | mitigate | Human legitimacy gate, exact versions, registry/source confirmation, lockfile replay, Maestro checksum verification, and full-SHA GitHub Actions. |
| T-01-02 | Information Disclosure | Android Auto Backup | mitigate | Generate and assert both backup rule families excluding databases and sensitive staging/no-backup paths per D-03. |
| T-01-03 | Elevation of Privilege | development-test route/config | mitigate | Separate application variant and generated/artifact assertions that test-only entry points are absent from non-development-test artifacts. |
| T-01-04 | Repudiation | APK identity | mitigate | Retain SHA-256 and build metadata for the exact installed artifact. |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | Package legitimacy audit plus blocking human verification for every SUS/ASSUMED package; SLOP packages are forbidden. |
</threat_model>
