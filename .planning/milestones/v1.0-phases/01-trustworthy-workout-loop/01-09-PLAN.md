<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Clock/lifecycle event → rest command | Time and process events may be repeated, delayed, or stale. |
| SQLite rest facts → Android scheduler | External notification state is disposable and permission-dependent. |
| Notification payload/tap → application | Payloads can be late, malformed, or from an older rest revision. |
| Android process lifecycle → restored UI | React memory disappears while persisted drafts/rest must remain authoritative. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09-01 | Tampering | rest commands | mitigate | Expected revisions, bound values, proven writer, explicit transition table, and coalesced effect key. |
| T-01-09-02 | Spoofing | notification payload | mitigate | Version/session/revision validation and fresh SQLite desired-state reload; payload never mutates workout facts. |
| T-01-09-03 | Denial of Service | repeated lifecycle/reconciliation | mitigate | Stable identifier, idempotent comparison, leased bounded retries, and coalescing uniqueness. |
| T-01-09-04 | Repudiation | process-death recovery | mitigate | Current-HEAD APK/digest-bound Maestro evidence and safe lifecycle diagnostics. |
| T-01-09-SC | Tampering | npm installs | mitigate | No new packages beyond the legitimacy-approved Expo Notifications dependency from 01-01. |
</threat_model>
