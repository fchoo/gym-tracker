<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| finish/discard input -> session outcome | Explicit intent and stale revisions control irreversible status changes. |
| committed session facts -> recommendation | Derived evidence must exclude invalid/non-comparable rows and remain replayable. |
| recommendation decision -> copied plan target | Stale evidence must not overwrite a newer target. |
| CI artifact -> emulator/physical device | Native, E2E, performance, and approval evidence must exercise identical bytes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10-01 | Tampering | outcome commands | mitigate | Explicit transition table, revision checks, destructive confirmation, and proven writer rollback. |
| T-01-10-02 | Tampering | recommendation evidence/acceptance | mitigate | Versioned stored evidence, warm-up/comparability exclusions, target revision check, and supersede path. |
| T-01-10-03 | Repudiation | CI/device proof | mitigate | Commit/APK SHA-bound manifests, uploaded/downloaded digest equality, JUnit/native JSON, and recorded physical evidence. |
| T-01-10-04 | Denial of Service | critical path performance | mitigate | Representative fixture, monotonic timings, >=100 samples, p95 budget, and main-thread long-task gate. |
| T-01-10-SC | Tampering | npm installs | mitigate | No new packages beyond the approved lockfile; CI uses npm ci and verified native/tool artifacts. |
</threat_model>
