### WR-01: Removed receipt equality guard left an unused occurrence-to-exercise map in the writer validator

**Classification:** **WARNING**

**Confidence:** 10/10

**File:** `/Users/bytedance/Documents/personal/gym_tracker/.trae/worktrees/p20-final5-review/src/platform/sqlite/repositories/logicalMergeRepository.ts:532-539`

**Issue:** The repair correctly switched receipt validation from current exercise equality to occurrence ownership, but `assertOwnedPlanAggregate` still builds `ownedOccurrenceExerciseIds` even though the map is no longer read:

```ts
const ownedOccurrenceIds = new Set<string>();
const ownedOccurrenceExerciseIds = new Map<string, string>();
for (const row of aggregate.tables.owned_plan_day_exercises ?? []) {
  const occurrenceId = textId(row.id);
  requireValid(!ownedOccurrenceIds.has(occurrenceId));
  requireValid(dayIds.has(textId(row.plan_day_id)));
  ownedOccurrenceIds.add(occurrenceId);
  ownedOccurrenceExerciseIds.set(occurrenceId, textId(row.exercise_id));
}
```

This is not a functional blocker, but it is dead validation-era state in an integrity-sensitive merge writer. It makes future reviewers think a current exercise binding is still consumed somewhere in the writer when the new intended invariant is only owned occurrence membership.

**Fix:** Remove the unused map declaration and setter, leaving only the occurrence set that the receipt binding validator consumes:

```ts
const ownedOccurrenceIds = new Set<string>();
for (const row of aggregate.tables.owned_plan_day_exercises ?? []) {
  const occurrenceId = textId(row.id);
  requireValid(!ownedOccurrenceIds.has(occurrenceId));
  requireValid(dayIds.has(textId(row.plan_day_id)));
  ownedOccurrenceIds.add(occurrenceId);
}
```
