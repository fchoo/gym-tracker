## Critical Issues

### CR-01: Keep-both replacement receipt replay returns stale invalidation scopes

**Classification:** **BLOCKER**

**Confidence:** 9/10

**File:** `/Users/bytedance/Documents/personal/gym_tracker/.trae/worktrees/p20-final5-review/src/domains/portability/mergePlan.ts:568-625`; `/Users/bytedance/Documents/personal/gym_tracker/.trae/worktrees/p20-final5-review/src/platform/sqlite/repositories/planImpactRepository.ts:1246-1258`; `/Users/bytedance/Documents/personal/gym_tracker/.trae/worktrees/p20-final5-review/tests/sqlite-host/logicalMergeRepository.test.ts:2619-2672`

**Issue:** The new receipt remap rewrites `planId`, `replacementExerciseId`, and `affectedOccurrenceIds`, but it preserves `result.invalidations` from the archive JSON. The original command result builds those invalidations from the archive command identifiers:

> `planImpactRepository.ts:1253-1257`
> ```ts
> invalidations: replacementInvalidations(
>   input.planId,
>   input.sourceExerciseId,
>   input.replacementExerciseId,
> ),
> ```

During keep-both merge, `rewriteExerciseReplacementReceipt` rewrites only these fields:

> `mergePlan.ts:619-624`
> ```ts
> result_json: encodeJson({
>   ...result,
>   planId,
>   replacementExerciseId,
>   affectedOccurrenceIds: rewrittenOccurrenceIds,
> }),
> ```

It validates that `invalidations` is an array, but does not rewrite any `plan:<id>` or `exercise:<id>` entries:

> `mergePlan.ts:609-611`
> ```ts
> || !Array.isArray(result.invalidations)
> || !result.invalidations.every((value) => typeof value === "string")) {
> ```

The new regression proves exact replay only by comparing the replay output to `mappedResult`, which was parsed from the already-stale remapped receipt:

> `logicalMergeRepository.test.ts:2625-2631`
> ```ts
> const mappedResult = JSON.parse(String(mappedReceipt.result_json));
> expect(mappedResult).toMatchObject({
>   outcome: "committed",
>   planId: mappedPlanId,
>   replacementExerciseId: "replacement",
>   affectedOccurrenceIds: [mappedReceipt.source_occurrence_id],
> });
> ```
>
> `logicalMergeRepository.test.ts:2667-2672`
> ```ts
> await expect(createPlanImpactRepository(reopenedKernel, {})
>   .applyExerciseReplacement(command))
>   .resolves.toEqual({
>     ...mappedResult,
>     outcome: "already_committed",
>   });
> ```

Impact: after a keep-both merge, exact replay can return `outcome: "already_committed"` while invalidating `plan:archive-plan` rather than the remapped `plan:<mappedPlanId>`. If custom exercise IDs are remapped, stale `exercise:<archiveExerciseId>` scopes can also survive. That breaks replayable/rebuildable projection semantics and can leave the actual merged plan caches/projections stale.

**Fix:** Rewrite or recompute invalidations while remapping the receipt. At minimum, translate `plan:<archivePlanId>` through `planIds`, and translate `exercise:<id>` through `exerciseIds` when present; fail closed on malformed scopes if this result is considered authoritative. Add assertions to the host regression that `mappedResult.invalidations` contains `plan:${mappedPlanId}` and contains no `plan:archive-plan`; add a custom-exercise keep-both case if replacement/source exercise remapping is possible.

Example fix shape:

```ts
function rewriteInvalidationScope(
  scope: string,
  planIds: ReadonlyMap<string, string>,
  exerciseIds: ReadonlyMap<string, string>,
): string {
  if (scope.startsWith("plan:")) {
    const source = scope.slice("plan:".length);
    return `plan:${mappedIdentifier(planIds, source)}`;
  }
  if (scope.startsWith("exercise:")) {
    const source = scope.slice("exercise:".length);
    return `exercise:${exerciseIds.get(source) ?? source}`;
  }
  return scope;
}

result_json: encodeJson({
  ...result,
  planId,
  replacementExerciseId,
  affectedOccurrenceIds: rewrittenOccurrenceIds,
  invalidations: result.invalidations.map((scope) =>
    rewriteInvalidationScope(scope, planIds, exerciseIds)
  ),
}),
```

### WR-01: Full-plan writer does not validate replacement receipt ownership or JSON binding

**Classification:** **WARNING**

**Confidence:** 8/10

**File:** `/Users/bytedance/Documents/personal/gym_tracker/.trae/worktrees/p20-final5-review/src/platform/sqlite/repositories/logicalMergeRepository.ts:361-489`; `/Users/bytedance/Documents/personal/gym_tracker/.trae/worktrees/p20-final5-review/src/platform/sqlite/repositories/logicalMergeRepository.ts:1264-1312`; `/Users/bytedance/Documents/personal/gym_tracker/.trae/worktrees/p20-final5-review/src/platform/sqlite/migrations/0047_plan_exercise_replacement_receipts.ts:24-37`

**Issue:** `plan_exercise_replacement_receipts` has no foreign keys in its schema:

> `0047_plan_exercise_replacement_receipts.ts:24-37`
> ```ts
> CREATE TABLE plan_exercise_replacement_receipts (
>   request_id TEXT PRIMARY KEY NOT NULL ...
>   plan_id TEXT NOT NULL ...
>   source_occurrence_id TEXT NOT NULL ...
>   replacement_exercise_id TEXT NOT NULL ...
>   ...
> ) STRICT
> ```

The writer now includes the table in `FULL_PLAN_OWNED_PLAN_TABLES` and blindly inserts/verifies rows by primary key:

> `logicalMergeRepository.ts:1269-1271`
> ```ts
> for (const table of FULL_PLAN_OWNED_PLAN_TABLES) {
>   await insertRows(transaction, table, aggregate.tables[table] ?? []);
> ```
>
> `logicalMergeRepository.ts:1309-1311`
> ```ts
> for (const table of FULL_PLAN_OWNED_PLAN_TABLES) {
>   await verifyRows(transaction, table, aggregate.tables[table] ?? []);
> ```

But `assertOwnedPlanAggregate` validates many child tables and stops after occurrence sources without checking replacement receipts:

> `logicalMergeRepository.ts:481-488`
> ```ts
> for (const row of aggregate.tables.owned_plan_occurrence_sources ?? []) {
>   requireValid(ownedOccurrenceIds.has(textId(row.plan_day_exercise_id)));
>   requireValid(dayIds.has(textId(row.plan_day_id)));
> }
> ```

Impact: the planner path has new receipt rewriting, but the transaction writer does not independently fail closed if a receipt row is malformed, bound to another plan, points outside the owned occurrence graph, or has JSON inconsistent with the remapped row. Because SQLite cannot catch these references, a future planner bug or corrupted internal handoff can persist bad immutable receipt facts and still pass `verifyRows`.

**Fix:** Extend `assertOwnedPlanAggregate` with explicit validation for `plan_exercise_replacement_receipts`: require `row.plan_id === operation.localId`, require `source_occurrence_id` in `ownedOccurrenceIds`, validate `replacement_exercise_id` is a known available exercise or intentionally external/bundled, validate `request_sha256`, `expected_plan_revision`, `result_plan_revision`, `committed_at_ms`, and parse `result_json` to ensure it agrees with the row after remap (`planId`, `replacementExerciseId`, `affectedOccurrenceIds`, `planRevision`, and rewritten invalidations). Add negative tests through `__logicalMergeRepositoryTestOnly.assertOwnedPlanAggregate` or `assertFullPlanSlice`.
