# Phase 18 — Garmin Import UI Design Contract

> Visual and interaction source of truth for GAR-01–GAR-16. Generated by gsd-ui-researcher for independent checker, planner, executor, and retrospective UI audit.

---

## Contract Boundary and Truthfulness Gate

Phase 18 delivers a complete, independently usable, offline original-FIT import journey; factual imported-activity detail; duplicate and source-revision review; and explicit matching to a stable Running opportunity.

Official Garmin connectivity is conditional:

- Production may show `Garmin API access needed` until actual Garmin program access, current partner documentation, and the separately reviewed confidential-credential topology all pass the ADR activation gate.
- `Disconnected`, consent, connected, syncing, no-new, error, and revoke states are production-reachable only when the approved provider capability says they are real.
- A local fixture, mocked adapter, simulated consent, hard-coded activity, or successful FIT import must never change the production capability to connected and must never close GAR-04–GAR-07.
- The confidential broker described as a possible future topology is **not authorized** by this phase. Do not implement, deploy, name endpoints for, or imply the existence of a broker.
- Manual FIT import, existing imported history, local detail, and local matching remain usable while the provider is unavailable, disconnected, offline, expired, or in error.

Prototype simulation controls (`Continue simulated consent`, `Preview Outdoor FIT`, `Preview Treadmill FIT`, `Preview error`) are fixture harness controls only. They do not appear in the application.

Sources: D18-01–D18-08, GAR-01–GAR-16, Garmin ADR activation gate, native NV-IMP-01–13, Revision 18 source-precedence resolution.

## Information Architecture and Contextual Routing

Garmin is a contextual stack inside the existing four-root shell. There is never a Garmin tab, fifth root, profile entry, or live-run recorder.

| Entry | Selected root retained | Destination | Return contract |
|-------|------------------------|-------------|-----------------|
| Workout root `Sync Garmin` | Workout | `app/garmin/index.tsx` | Android Back from Garmin root returns to the exact Workout anchor and scroll position |
| Running plan `Sync Garmin / match activity` | Library | `app/garmin/index.tsx` | Android Back returns to the exact Running plan route and scroll position |
| Imported Calendar event row | Calendar | `app/garmin/activity/[activityId].tsx` | Back restores the focused date, agenda state, event focus, and scroll anchor |
| Connected/imported activity row | Entry origin remains selected | `app/garmin/activity/[activityId].tsx` | Back returns to Garmin activities |
| `Match to scheduled workout` | Entry origin remains selected | `app/garmin/match/[activityId].tsx` | Back returns to the same activity detail without writing a match |
| `Import FIT` | Entry origin remains selected | `app/garmin/import.tsx` | Back returns to Garmin activities; picker cancellation stays on Import FIT |

Only an internal validated `workout | calendar | library | progress` origin and an opaque local activity identity may travel through route params. Never accept an arbitrary return URL, provider URL, filename, account subject, or raw external activity ID as a navigation target.

### Header contract

- The app bar uses a stable `48dp / minmax / 48dp` three-column grid, minimum 62dp high at 1× text, 12dp horizontal inset, a hairline bottom divider, and safe-area clearance. These off-scale values are exact owner-approved prototype exceptions backed by `approved-hybrid.html:1481` / `.garmin-header`.
- The center route heading is centered independently of either side action.
- At Garmin root the title is exactly `Garmin Sync` on one line. The 48dp left slot remains reserved by a disabled, hidden, non-focusable, non-accessible placeholder. The appearance action stays flush right.
- Deep titles are exactly `Connect Garmin`, `Import FIT`, `Confirm activity date and time`, `Activity detail`, `Match activity`, or `Review activity update`. The left slot becomes a real 48×48dp Back control. Deep titles may grow the header to two lines at 200% text; they must never truncate required meaning.
- Back labels are route-specific: `Back to Garmin activities`, `Back to activity detail`, or `Back to FIT import`. The icon is decorative; the button owns the label.
- The right control is a 48×48dp outlined appearance icon labelled `Open Garmin appearance` on every Garmin route.
- Android Back/Escape dismisses the topmost sheet first, then returns one Garmin route, then returns from Garmin root to its entry origin. It never changes source facts.
- Switching one of the four bottom roots closes the Garmin stack and restores that root's retained state.

### Content frame

- One vertical scroll region fills the space between the 62dp header and the bottom navigation plus device safe area.
- Compact reference inset is 18dp horizontal, 14dp top, and 32dp bottom. The 18/14 values are exact owner-approved prototype exceptions backed by `approved-hybrid.html:1485` / `.garmin-scroll`; they are component measurements, not reusable spacing tokens.
- Bottom navigation remains a bottom composition at compact, medium, expanded, portrait, and landscape widths; no automatic rail substitution.
- The selected bottom item is always the contextual origin, never Garmin.

- Body line height is 1.5. Route heading line height is approximately 1.2.

## Official Provider State Contract

### Reachability rule

`approval_needed` is the production default while the approval gate is known to be closed. `capability_unavailable` is distinct: the capability cannot currently be used or established. `authorization_revoked` is a provider result that invalidates a previously connected authorization. Every connected-path row is conditional on a real, approved provider capability. Test fixtures may render these rows but must be visibly test-only and cannot alter production capability or verification status.

## Independently Usable FIT Import Contract

The local path works without network, Garmin login, developer approval, provider credentials, or a broker.

Phase 18 accepts one uncompressed original `.fit` file. It does not parse ZIP files, exported archives, or arbitrary archive entries. ZIP support requires actual owner export evidence plus separately reviewed expansion-size, entry-count, path, cleanup, and native-memory bounds; it is not added speculatively.

### Initial and picker states

| State | Exact presentation | Controls and focus |
|-------|--------------------|--------------------|
| Initial | Route `Import FIT`. Info banner `Import original activity file`; body `Choose one original .FIT activity file. Gym Tracker reads it locally and does not need Garmin API access.` Supporting copy `The same activity is not added twice. Updated source files are reviewed before accepted facts change.` | Primary `Choose FIT file`; secondary `Cancel FIT import`. Header Back is labelled `Back to Garmin activities`. Initial focus is the route heading, then picker action |
| Native picker open | Android system original-file picker; one file only; request read-only access | Do not request broad storage, location, Garmin login, or background permission |
| Picker cancelled | Stay on `Import FIT` with no error, toast, receipt, or source write | Restore focus to `Choose FIT file` |
| Reading/validating | Banner `Reading FIT file`; body `Checking file integrity and activity data.` Static progress plus busy semantics | `Cancel FIT import` is available only before the commit boundary; duplicate activations disabled |
| Date/time confirmation required | Route heading `Confirm activity date and time`. Attention body `This FIT file does not include a reliable time zone. Confirm when this activity happened before importing it.` Facts show `Proposed date`, `Proposed time`, and `Time zone` with explicit values | `Change date/time`, primary `Confirm activity date`, and `Cancel FIT import`. No source fact, receipt, or match write exists yet |
| Committing | Banner `Importing activity`; body `Saving the checked activity.` | The `Cancel FIT import` action is absent after the exclusive transaction begins; do not announce success before commit |
| New import committed | Navigate to `Activity detail` and show committed source facts. Polite result `{Activity name} imported.` | Focus route heading; Back returns to Garmin activities |

Selecting a valid new FIT file with reliable date/time-zone provenance authorizes import. Do not add an extra generic confirmation modal in that case. The factual post-commit Activity detail is the preview/review surface. The prototype's canned Outdoor/Treadmill preview buttons are not product controls.

When the source time zone is absent or ambiguous, import pauses before any SQLite source fact or receipt write:

1. Derive one review proposal without asserting it as fact. Display `Proposed date`, `Proposed time`, and `Time zone`, including the full zone name/offset used for the proposal.
2. `Change date/time` expands explicit date, local time, and time-zone controls inline. Edited values replace the displayed proposal, while `Confirm activity date` remains the only action that can proceed to commit; editing alone writes no imported activity.
3. `Confirm activity date` records the confirmed date/time-zone provenance as part of the subsequent exclusive import transaction.
4. `Cancel FIT import` or header `Back to Garmin activities` cleans temporary bytes and writes nothing.
5. A process interruption before confirmation returns to `FIT import was interrupted`; it must not infer consent from the abandoned proposal.

### FIT failure and recovery copy

| Failure | Heading | Body | Actions |
|---------|---------|------|---------|
| Wrong/non-FIT file | `FIT file could not be imported` | `This is not a supported FIT activity file. Choose an original .FIT activity file.` | `Choose another file`, `Cancel FIT import` |
| ZIP/archive selected | `ZIP files are not supported` | `Extract the original .FIT file first, then choose that file.` | `Choose another file`, `Cancel FIT import` |
| Malformed/CRC-invalid/truncated | `FIT file could not be imported` | `This FIT file is incomplete or damaged. Export the original activity again and retry.` | `Choose another file`, `Cancel FIT import` |
| Unsupported/multisport | `Activity type is not supported` | `Choose one original FIT file containing a supported running activity. Multisport files are not imported in this version.` | `Choose another file`, `Cancel FIT import` |
| Oversized/resource bound | `FIT file is too large` | `This file cannot be imported safely on this device. Choose a smaller original activity file.` | `Choose another file`, `Cancel FIT import` |
| Missing/invalid required session facts | `Activity could not be read` | `The file does not contain one supported running session with a valid date and duration.` | `Choose another file`, `Cancel FIT import` |
| Decoder/runtime failure | `FIT import could not finish` | `Nothing was added. Try another original FIT file.` | `Choose another file`, `Cancel FIT import` |
| SQLite/commit failure | `Import could not be saved` | `Nothing was added. Your existing activities are unchanged. Try again.` | `Try again`, `Cancel FIT import` |
| Interrupted before commit | `FIT import was interrupted` | `Nothing was added. Choose the original FIT file again to retry.` | `Choose FIT file`, `Cancel FIT import` |
| Lost acknowledgement after commit | Open the committed activity; polite result `Import recovered. No duplicate was added.` | No error page | `View activity` |

Errors never expose a content URI, filesystem path, filename, provider subject, raw coordinate, raw decoder exception, token, device serial, or private FIT bytes. Use a classified diagnostic code only behind the existing diagnostic affordance.

## Activity Subtype Outcome Contract

Sport/subtype comes from validated FIT facts, never from the presence or absence of GPS. In particular, missing coordinates must never classify an activity as treadmill.

| Validated source classification | Supported outcome and exact detail copy | Recovery / guard |
|---------------------------------|-----------------------------------------|------------------|
| Explicit outdoor running + valid coordinates | Import as Outdoor Run and render the factual local route | Invalid/sentinel/gapped coordinates are excluded; do not connect through placeholders |
| Explicit outdoor running + no usable coordinates | `Route unavailable` / `This outdoor activity did not include route coordinates. Distance, time, pace, and laps remain available.` | Keep subtype Outdoor. Never relabel as treadmill |
| Explicit treadmill running | `No route for treadmill activity` / `Distance, time, pace, and laps remain available.` | Show no map and request no location permission, even if stray coordinate records exist |
| Explicit indoor running, not treadmill | `No route for indoor activity` / `This activity is marked as an indoor run. Distance, time, pace, and laps remain available when present.` | Preserve subtype Indoor. Do not relabel as treadmill or outdoor |
| Base sport is running; subtype absent/unknown | `Route unavailable for unspecified run` / `This FIT file does not identify this run as outdoor, treadmill, or indoor. No route or subtype was inferred. Available distance, time, pace, and laps are shown.` | Persist a supported unspecified-running subtype only; GPS presence/absence does not resolve it |
| Base sport is absent/unknown or not a supported running activity | `Activity type could not be confirmed` / `This FIT file does not identify one supported running activity. Nothing was added. Choose another original FIT file.` | Reject before source writes; actions `Choose another file` and `Cancel FIT import` |
| Explicit unsupported/multisport session | `Activity type is not supported` / `Choose one original FIT file containing a supported running activity. Multisport files are not imported in this version.` | Reject before source writes; actions `Choose another file` and `Cancel FIT import` |

The activity/source badge must say `Outdoor`, `Treadmill`, `Indoor`, or `Running · subtype not identified` from the persisted classification. It must not claim a more specific subtype later because a projection found or failed to find coordinates.

## Imported Activity Detail

### Shared structure

1. `Activity detail` header.
2. Committed-success source banner with activity name and `{Source} · imported {date · time}`.
3. Optional factual route or explicit missing-route message.
4. Facts grid.
5. Optional Average heart rate row.
6. Laps section.
7. Full-width `Match to scheduled workout`.

This route is read-only. It never edits source values, creates a plan, activates a plan, completes a strength workout, or matches a schedule without the separate confirmation route.

### Canonical facts and pace basis

The source-present fact order is always:

1. `Distance`.
2. `Elapsed`.
3. `Moving` only when moving-time provenance is independently verified; otherwise `Timer` when a valid timer-running duration exists.
4. `Avg pace`.

Missing facts are omitted and the remaining facts close the gap without changing order:

- Four facts: compact 1× uses a 2×2 grid (`Distance / Elapsed`, then `Moving or Timer / Avg pace`); medium/expanded may use one four-column row.
- Three facts: one three-column row when it fits; otherwise 2+1 in order.
- Two facts: one two-column row.
- One fact: one full-width row.
- At 200% or any measured collision: one stacked label/value row per fact in canonical order.

`Avg pace` uses this deterministic basis:

1. Preserve a valid source session average-pace/average-speed fact when its basis is present in accepted source evidence.
2. Otherwise compute from positive verified Timer duration divided by positive Distance.
3. Otherwise compute from positive Elapsed duration divided by positive Distance.
4. Never compute pace from a heuristic or unverified Moving value. If neither a valid source pace nor a positive supported time basis and distance exist, omit `Avg pace`.

The accepted source evidence stores `source summary`, `Timer`, or `Elapsed` as the pace basis. The value's accessibility label includes it, for example `Average pace, 5 minutes 51 seconds per kilometre, based on elapsed time`. A later source revision cannot silently change this basis.

### Outdoor

- If valid coordinates exist, draw a 165dp static SVG route from those coordinates only. The accessible label is `Route for {activity name}; {distance} from {start area if source-provided, otherwise no location name}`.
- Do not use the prototype's synthetic curve, map tiles, live location, road inference, or GPS permission.
- If coordinates are absent, show info heading `Route unavailable` and body `This outdoor activity did not include route coordinates. Distance, time, pace, and laps remain available.` Never reclassify it as treadmill.
- Facts follow the canonical source-present order `Distance`, `Elapsed`, verified `Moving` or `Timer`, `Avg pace`. Omit a fact that is genuinely absent; never display zero or an empty tile as a substitute.
- Show `Average heart rate` as a spaced label/value row only when the source supplies an accepted summary. An absent heart-rate row is omitted, never `0 bpm`.

### Treadmill

- Show the exact heading `No route for treadmill activity`.
- Body is exactly `Distance, time, pace, and laps remain available.`
- Never render a blank map frame or request GPS/location permission.
- Facts follow the same canonical source-present order. `Moving` is shown only with verified provenance; otherwise show `Timer` when present. Treadmill never gains a route from missing/present GPS heuristics.

### Indoor and unspecified running

- Explicit Indoor detail uses `No route for indoor activity` and the exact body from the subtype table.
- Supported unknown subtype detail uses `Route unavailable for unspecified run` and the exact body from the subtype table.
- Both use the canonical fact order and the same HR/lap rules. Neither is presented as treadmill, outdoor, or a map surface.

### Laps

- Headers are exactly `Lap`, `Time`, `Pace` in that order.
- Preserve imported lap semantics and order. Do not turn cumulative treadmill checkpoints into splits or invent one-kilometre laps.
- Prefer verified lap timer time for `Time` under the ADR convention. Missing values render visual `—` with accessible value `Not available`.
- If no laps are present, show heading `No lap data` and body `This activity did not include lap data.` Do not render an empty table.
- At normal compact layout use three columns: Lap left aligned, Time/Pace right aligned in IBM Plex Mono. At 200% or when values collide, each lap becomes a vertically growing row with repeated visible labels `Lap`, `Time`, `Pace` in the same reading order. Required information is never reachable only through horizontal scrolling.

### Detail loading/recovery

| State | Copy | Action |
|-------|------|--------|
| Loading | `Loading activity` / `Reading imported activity facts.` | Static skeleton; Back available |
| Missing/deep-link invalid | `Activity not found` / `This imported activity is unavailable or was removed.` | `Back to Garmin activities` |
| Projection failure | `Activity could not be opened` / `Your imported activity is still saved. Try loading the detail again.` | `Try again`, Back |
| Removed/tombstoned | `Activity was removed` / `Its historical removal is preserved. Importing the same file will not restore it automatically.` | `Back to Garmin activities` |

## Dedupe, Identity Conflict, and Source Revision Review

The interface reflects the two independent identity indexes: verified provider subject/external activity ID when available, and SHA-256 of exact FIT bytes. Similar time/distance is never an automatic merge.

| Outcome | Exact UI and controls | Committed or zero-write outcome |
|---------|-----------------------|---------------------------------|
| Same hash/exact replay | Heading `Already imported`; body `This FIT file matches {activity name} from {date}. No duplicate was added.` Controls `View activity`, `Choose another file`, `Back to Garmin activities` | Replay the existing receipt; create no source rows, activity, match, or new dedupe decision |
| API delivery matches manual hash | Heading `Existing activity found`; body `This Garmin delivery matches an activity already imported from FIT. No duplicate was added.` Controls `View activity`, `Back to Garmin activities` | Only after coherent owner/provider-subject verification, atomically record the additional verified source reference and delivery receipt against the existing activity. Otherwise route to `Activity identity needs review`. Never create/merge a second aggregate |
| Same external ID, changed hash | Heading `Activity update needs review`; body `Garmin supplied a different file for an activity already in your history. Your accepted facts have not changed.` Controls `Review changes`, `Keep current activity`, `Back to Garmin activities` | Stage an immutable proposed revision. Accepted facts and existing match stay unchanged until the separate review commits |
| Different IDs, same hash | Heading `Activity identity needs review`; body `Two Garmin references point to the same recording. Review the source identities before continuing.` Controls `Review source identities`, `Cancel FIT import` | Open the dedicated source-identity review below. No alias/additional-source decision is permitted before coherent ownership is proven; never silently merge |
| External ID resolves to A, hash to B | Error heading `Activity identity conflict`; body `The Garmin identity and file content point to different activities. Nothing was changed.` Controls `Choose another file`, `Back to Garmin activities` | Block import, merge, aliasing, matching, receipts, and all source writes |
| Similar totals, different bytes | Attention heading `Possible duplicate`; body `This activity looks similar to one already in your history, but the files are different. Review both before deciding.` Controls `Import as separate activity`, `View existing activity`, `Cancel FIT import` | `Import as separate activity` atomically records the new activity, import receipt, and explicit kept-separate decision. View/cancel writes nothing. Never auto-merge |
| Reimport removed activity | Heading `This activity was removed`; body `Importing the file again will not restore it automatically.` Controls `Review removed activity`, `Cancel FIT import` | Preserve the tombstone and open the separate audited restore route below. Reimport itself writes nothing and never resurrects or matches the activity |

### `Review source identities` destination

- `Review source identities` opens the `sourceIdentityReview` state of `app/garmin/import.tsx` using opaque local candidate/activity IDs only. The route heading is exactly `Review source identities`.
- Present `Existing activity source` and `Proposed additional source`, each with provider label, imported date, content-match statement, and non-sensitive ownership/coherence result. Never show a raw provider subject or external activity ID.
- While ownership/account coherence is unknown or failed, there is no commit action. Show `Source ownership could not be confirmed` / `No source reference was added. Choose another file or return to Garmin activities.` with `Choose another file` and `Back to Garmin activities`.
- After coherent ownership is proven, the permitted primary action is `Add verified source reference` and the secondary action is `Cancel FIT import`. This action adds an alias/additional-source reference to the existing aggregate; it does not merge two activities, replace an accepted payload, or create a match.
- `Add verified source reference` commits the additional reference and decision receipt atomically. Success copy is `Verified source reference added.` Failure is `Source reference could not be added` / `Nothing was changed. Review the source identities and try again.` with `Try again` and `Cancel FIT import`.

### Possible-duplicate decision

- `View existing activity` opens the existing `Activity detail` read-only route. Back returns to the same `Possible duplicate` decision with the candidate and focus context intact; viewing writes nothing.
- `Import as separate activity` opens confirmation `Import as a separate activity?` / `The FIT files are different. This creates another activity and records that you chose to keep them separate. It will not match a scheduled workout automatically.`
- Confirmation controls are `Import as separate activity` and `Cancel FIT import`.
- Confirm commits the new activity, import receipt, and explicit kept-separate decision in one exclusive transaction. Success appears only after commit; failure copy is `Separate activity could not be imported` / `Nothing was added. Review the possible duplicate and try again.`

### `Review removed activity` route

- `Review removed activity` opens the separate audited `app/garmin/activity/[activityId]/restore.tsx` route with heading `Review removed activity`. It shows the removed activity's factual summary and removal date/revision when available.
- Copy is `This activity remains removed. Restoring it is a separate audited action; importing the same FIT file does not restore it.`
- Primary `Restore removed activity` opens confirmation `Restore removed activity?` / `This records a new restore event for the existing activity. It does not create a new activity or match a scheduled workout.`
- Confirmation controls are `Restore removed activity` and `Keep activity removed`. The import-route exit remains `Cancel FIT import`.
- Restore appends a revision-checked audit event and reuses the existing activity/payload identity in one exclusive transaction. It creates no duplicate activity and no match. Failure is `Activity could not be restored` / `The activity remains removed. Try again.` with `Try again` and `Keep activity removed`.

### Dedupe focus, Back, and zero-write exits

- Every dedupe/identity/removed outcome moves focus to its heading and announces the result once.
- `Review source identities` and `Review removed activity` move focus to their route headings. Back returns to the immediately preceding outcome with the same candidate context and writes nothing.
- `View activity` and `View existing activity` move focus to `Activity detail`. Back restores the originating decision and focused control; viewing writes nothing.
- `Choose another file` returns to the native picker after clearing only the uncommitted candidate bytes. `Cancel FIT import` returns to Garmin activities and clears the uncommitted candidate. `Back to Garmin activities` exits without a decision. All are zero-write exits.
- Only `Add verified source reference`, `Import as separate activity`, `Use updated activity`, and `Restore removed activity` may write their named decisions. Each publishes success and moves focus only after its exclusive transaction commits.
- No dedupe decision creates or changes a scheduled-workout match.

### `Review activity update` state

- Show `Current accepted activity` and `Proposed update` in a single scroll, using the same field order: source/date, distance, elapsed, verified timer/moving, average pace, average heart rate, route availability, lap count.
- Every changed row includes visible `Changed` text and an accessible state; color is secondary.
- Exact copy above the comparison: `Review the source changes. Your current accepted activity stays unchanged until you choose the update.`
- If a confirmed match references the old payload, show attention copy: `Matched evidence changed` / `The existing match keeps the activity revision it used. Review any match change separately.`
- Primary `Use updated activity` opens confirmation: `Use updated activity facts?` / `This accepts the proposed source revision. Historical revisions remain recorded.`
- Secondary `Keep current activity` rejects or leaves the proposal pending according to the domain command; Back performs no acceptance.
- Pending label is `Saving activity update…`. Success is `Activity update accepted.`
- Failure is `Activity update could not be saved` / `Your current accepted activity is unchanged. Try again.` with `Try again` and `Keep current activity`.
