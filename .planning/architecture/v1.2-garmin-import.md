# ADR: Standalone Android Garmin Connect account import

**Status:** Accepted for v1.2 planning
**Date:** 2026-10-07
**Authority:** .planning/v1.2-OWNER-DECISIONS.md
**Implementation authorization:** Not granted by this ADR

## Decision

Gym Tracker will ship one self-contained ARM64 Android application which embeds Python 3.13 through Chaquopy 17.0. The app bundles python-garminconnect 0.3.17 at commit 218e72ca5459e014435fc2d94fd18bd601fa0c14 and the exact curl_cffi Android wheel curl_cffi-0.15.0-cp313-abi3-android_24_arm64_v8a.whl with SHA-256 4682dc38d4336e0eb0b185374db90a760efde63cbea994b4e63f3521d44c4c92.

The native module logs the owner into their Garmin Connect account, handles MFA, restores encrypted DI tokens, and reads bounded JSON through four allowlisted upstream methods. TypeScript normalizes those responses into GarminSourceEnvelope and passes the envelope to the shared Phase 13 import commands. SQLite repositories remain the only persistence authority. A match to a planned Running occurrence remains a separate explicit confirmation.

This milestone does not use Garmin Developer Program credentials, an official Activity API, a confidential service, a desktop helper, a Drive inbox, a FIT decoder, or manual original-file import. Failure of the selected native proof records TECHNICAL_REVIEW_REQUIRED; it does not select another topology.

## Authentication and token lifecycle

1. login receives email/password in foreground memory and returns either connected, mfa_required with an opaque challenge handle, or a classified failure.
2. resumeMfa accepts the opaque handle plus code. Password and MFA code references are cleared after the operation and never enter React state, logs, evidence, SQLite, logical backup, or Drive.
3. python-garminconnect dumps and loads only DI session tokens through dependency injection supplied by GarminTokenStore. Upstream automatic disk persistence is disabled or redirected to that injected store.
4. GarminTokenStore encrypts token bytes with an Android Keystore non-exportable AES-GCM key. It writes nonce, ciphertext, version, and integrity metadata to app-private storage using replace-after-fsync semantics.
5. A refresh rotates encrypted token state only after the new ciphertext is durably readable. Interrupted rotation retains the last valid record.
6. restoreSession loads the encrypted record after process restart and proves one authenticated read. A JWT_WEB-only state is never claimed restart-capable unless a DI token record is present.
7. logout increments the in-memory connection generation before clearing tokens and Python client state. Prior imported activities remain. Late work from an older generation is discarded before normalization or persistence.

Token and credential paths are explicitly excluded from Android cloud backup and device transfer. Logical archive code never sees them.

## JSON acquisition contract

Foreground sync uses one serialized client. It reads recent pages with get_activities(start, limit, activitytype, activitysubtype), then reads each selected activity through get_activity, get_activity_splits, and get_activity_details(maxchart=2000,maxpoly=4000).

The adapter enforces:

- integer bounded pagination and a configured maximum activities per foreground attempt;
- exact external activity identifier validation before crossing the bridge;
- per-component byte and nesting limits before TypeScript parsing;
- one in-flight foreground sync and one connection generation;
- bounded timeout/retry rules with no login loop;
- no persistence from a partial activity component set;
- cancellation at page/activity boundaries, with already committed prior activities retained;
- privacy-safe diagnostics containing codes, counts, timings, and opaque receipt IDs only.

403 after successful authentication is a distinct data_access_denied result, matching the risk described in upstream issue #444. It does not claim logout or delete the last valid token record. 429 becomes rate_limited with a validated/clamped retry-after value when supplied; the UI never spins or fabricates success. Offline, timeout, 5xx, malformed JSON, and unsupported sport are separate typed outcomes.

## Canonical payload and source identity

canonicalGarminPayload.ts recursively validates plain JSON, sorts object keys by binary code-unit order, preserves array order, rejects non-finite numbers and unsafe integers, omits absent optional channels rather than writing zero, and emits one UTF-8 canonical representation. Attempt times, fetch times, connection state, retry metadata, and UI fields never enter normalized_json_sha256.

raw_component_sha256 contains the SHA-256 of each independently canonicalized pre-normalization component: activity, splits, and details. It is provenance, not the accepted semantic identity. normalized_json_sha256 covers the final CanonicalGarminPayload plus normalization_version. Both are lower-case 64-character hexadecimal values.

Identity is owner namespace + source_kind + account_namespace + external_activity_id, with normalized content digest used to detect exact replay or changed source revision. Title, date, distance, pace, and route similarity never merge two activities. fit_sha256 is structurally absent.

sample_fidelity is explicit:

- source_laps when a fact is retained directly from source lap/split semantics;
- source_summary when retained directly from the activity summary;
- sampled for chart/polyline channels returned under maxchart/maxpoly limits.

Elapsed, timer, and moving remain separate optional facts with explicit source basis. Missing channels remain absent. Exact arbitrary-distance best efforts may use eligible source-reported summary/lap evidence only; sampled chart/polyline data yields More data needed.

## Shared import and idempotency

normalizeGarminActivity produces GarminSourceEnvelope and calls the Phase 13 command surface:

- prepareGarminImport(envelope) validates bounds, identity, normalized content, source revisions, portability capacity, and current owner namespace;
- confirmGarminImportDate(...) is used only when source time-zone/local-date provenance needs explicit confirmation;
- the Phase 13 repository rechecks all constraints inside one exclusive transaction and returns only after the source aggregate, immutable payload, source reference, laps/chunks, receipt, and dirty generation commit;
- exact replay returns the existing activity/receipt; changed normalized content under the same external identity stages review without replacing accepted history;
- a source revision never rewrites a payload pinned by an existing match.

Phase 18 adds no provider-specific SQLite table and never calls SQL from a route, screen, Python module, or native worker.

## Presentation and matching

Garmin remains a contextual stack under exactly four roots. Production routes are:

- app/garmin/index.tsx
- app/garmin/activity/[activityId].tsx
- app/garmin/match/[activityId].tsx

Workout and Running-plan entries pass only a validated local origin. Calendar consumes the opaque local activity-detail route. Back uses the navigation stack and bounded return state; arbitrary href values and raw external IDs are rejected.

Outdoor detail renders available distance, elapsed, timer/moving, pace, optional route, optional average heart rate, laps, and source-fidelity disclosure. Treadmill says No route and retains factual distance/time/pace/laps. The accessible table columns are Lap, Time, Pace. Missing values remain unavailable, not zero.

Candidate queries use the stable Phase 17 occurrence/slot/revision identity. Radio selection is local. Confirm match alone calls the Phase 13 revision-fenced match command; Back and Leave unmatched write nothing. Unmatch/reassign append audited events.

## Portability and privacy

Accepted source envelopes and match events follow the Phase 13 logical portability contract. Encrypted Garmin tokens, Python client state, connection cursors, retry metadata, native raw JSON staging, and evidence artifacts are not portable. Restore starts disconnected and cannot resurrect authorization.

Route/HR samples and account identifiers never enter diagnostics or committed native evidence. Test fixtures are synthetic or redacted canonical JSON. Live proof records only artifact identity, result codes, counts, timings, and hashes.

## Proof ordering

The earliest native proof follows the committed packaging/authentication harness and must establish on ARM64:

1. Python/client/native imports from the installed APK with no external Python, terminal, Metro server, or downloaded script.
2. Real foreground login and MFA when required.
3. One authenticated Running activity read.
4. Encrypted DI token restore and refresh after process restart.
5. No credential/token/raw activity leakage in logcat, evidence, or backup paths.

Later adversarial proof covers logout, stale-generation cancellation, issue-#444-style 403, 429, offline, timeout, malformed JSON, partial failure, token rotation interruption, and receipt replay. Any first-proof failure records exact stage, classified code, artifact identity, and bounded logs as TECHNICAL_REVIEW_REQUIRED. It neither marks the phase complete nor changes product architecture.

## Threat model summary

| Threat | Severity | Disposition | Control |
|---|---|---|---|
| Credential or token disclosure | critical | mitigate | foreground secret lifetime, encrypted DI store, redacted logs/evidence, backup exclusions |
| Arbitrary Python/native invocation | critical | mitigate | fixed typed bridge and method allowlist; no eval/URL/method forwarding |
| Stale account result writes after logout/reconnect | high | mitigate | connection generation checked before normalize/import |
| Dependency or wheel substitution | high | mitigate | exact commit/version/ABI/filename/hash lock and build-time verification |
| Garmin response/resource exhaustion | high | mitigate | page/component/nesting/count/time bounds and serialized foreground sync |
| Sampled data presented as exact evidence | high | mitigate | sample_fidelity and source-basis gates |
| Duplicate or revision silently rewrites history | high | mitigate | scoped external identity, canonical digest, immutable revisions, receipt replay |
| Restore resurrects authorization | high | mitigate | tokens/cursors excluded; restored app starts disconnected |

## Consequences

- APK size increases because it carries Python, Chaquopy, curl_cffi, and transitive native code.
- The selected artifact supports Android ARM64; x86 emulator proof is not claimed.
- Upstream unofficial endpoints can change and may fail despite successful login. Those failures remain visible, recoverable technical states.
- Library/client updates require a new reviewed lock and APK; runtime downloading is prohibited.
- Existing offline Strength workout behavior and SQLite authority remain unchanged.
