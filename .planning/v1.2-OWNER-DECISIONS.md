## Standalone application

The owner wants an installed standalone app. Runtime operation must not require
Trae, GSD, Codex, Claude, an LLM, an AI agent, a development terminal, a Metro
server, or a desktop helper. Bundled ordinary JavaScript/Python/native code is
the selected architecture; it is not dynamically invoked AI.

Hermes is React Native's embedded JavaScript engine. There is no owner-selected
requirement to adopt or switch to a particular JavaScript engine. Retain the
framework-supported runtime unless a separate technical reason requires a
change. If Python is selected, it is packaged inside the APK and called through
native methods; no on-device pip installation or remote script/agent loading.

## Shared transport contract for the final plan

- Proposed module: `modules/garmin-connect/`; TypeScript adapter under
  `src/platform/garmin/`. A Kotlin worker calls bundled Python through Chaquopy;
  there is no Python subprocess/local HTTP server, on-device pip, downloaded
  script, development server or runtime AI agent.
- Credentials and MFA are foreground owner interactions. Persist DI session
  tokens with Android Keystore-backed encryption outside logical backups and
  Drive. Do not silently retain passwords or claim JWT_WEB-only sessions survive
  restart; the real-account proof must cover refresh/cold restart.
- A narrow typed port exposes login/MFA/logout, paged Running summaries, one
  activity, splits and details. No arbitrary eval, method/URL forwarding, Garmin
  upload/delete APIs, service-account scraping, broker or official partner keys.
- Source identity: owner/account namespace + `garmin_connect_account` + external
  activity ID. Payload identity: versioned canonical normalized JSON content
  digest, excluding attempt/fetch times; retain separate raw response component
  hashes/provenance. `fit_sha256` remains absent when no original FIT exists.
  Manual/API/FIT histories must never be coalesced by date/title/distance alone.
- Normalize through the common imported-activity domain; native/Python networking
  never writes workout SQL. Recheck the source/capacity/revision fence before
  one exclusive transaction; matching remains a separate explicit owner action.
- JSON chart/polyline limits mean sampled detail is not proof of full-resolution
  data. Use only eligible source-reported summary/lap evidence for exact distance
  efforts; otherwise show More data needed. Do not invent arbitrary-distance
  best efforts from downsampled charts. FIT can be reconsidered later only if
  required facts cannot be faithfully supplied.
- Native packaging, MFA, authenticated reads, fresh/expired session restart,
  403/429 handling, bounded sync, encrypted token rotation, sampled-data honesty,
  idempotency and standalone APK operation are technical acceptance cases.
  A native proof using the owner's account may need their sign-in/MFA, but that
  is a runtime interaction, not an unresolved architectural decision.
