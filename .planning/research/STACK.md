# Technology Stack

**Project:** Gym Tracker  
**Researched:** 2026-08-16  
**Overall confidence:** HIGH for Expo/Android/test tooling; MEDIUM for the app-owned Argon2id bridge until device benchmarks and known-answer tests pass

## Recommended Stack

### Core Framework

| Technology | Version / range | Purpose | Why |
|------------|-----------------|---------|-----|
| Node.js | `24.19.0` exact | Local and CI JavaScript runtime | Current Node 24 LTS; satisfies React Native 0.86.2's `^24.3.0` engine range. Pin in `.nvmrc`, CI, and release metadata. |
| npm | `11.17.0` exact | Package manager | Bundled with Node 24.19.0. Commit `package-lock.json`, declare `packageManager: "npm@11.17.0"`, and use `npm ci`. |
| Expo SDK | `~57.0.13` | Application platform and CNG owner | Current stable SDK. Use Expo's patch range and `npx expo install`; never mix in a newer standalone React Native. |
| React | `19.2.3` exact | UI runtime | Exact version from the Expo SDK 57 template. |
| React Native | `0.86.2` exact | Native UI/runtime | Exact Expo SDK 57 compatibility target. Do not install React Native 0.87 independently. |
| TypeScript | `~6.0.3` | Language and compiler | Expo SDK 57 template version. Enable `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes`. |
| Expo Router | `~57.0.13` | Four-tab shell and focused workout routes | Expo-managed Router version. Install with `expo install`; application code should import navigation APIs from `expo-router`, not direct `@react-navigation/*` internals. |

**Version rule:** retain Expo-generated `~57.x` ranges for Expo-owned packages, exact-pin React and React Native as generated by the SDK template, and exact-pin non-Expo application libraries. The lockfile is the reproducible dependency graph. Dependabot may propose updates, but native or Expo updates merge only after `expo install --check`, clean prebuild, device SQLite tests, and Maestro smoke pass.

### Local Data and Platform Modules

| Technology | Version / range | Purpose | Native implications |
|------------|-----------------|---------|---------------------|
| `expo-sqlite` | `~57.0.1` | Authoritative workout facts, migrations, FTS5, effects, and projections | Configure `enableFTS: true`; initialize `WAL` and foreign keys; use `withExclusiveTransactionAsync()` for multi-statement writes. Validate semantics against actual Expo SQLite on Android. |
| `expo-notifications` | `~57.0.11` | Local rest-completion notification projection | Requires its config plugin and a development/native build. Create a stable Android rest channel before requesting Android 13+ permission. Notifications remain disposable; SQLite rest state is authoritative. |
| `expo-haptics` | `~57.0.1` | Best-effort set-completion feedback | Android `VIBRATE` permission is added automatically. Haptics never acknowledge persistence and must honor the user's setting. |
| `expo-crypto` | `~57.0.1` | Random bytes and AES-256-GCM backup encryption | SDK 57 provides native AES-GCM. Use a 32-byte key, 12-byte nonce, 16-byte tag, and authenticated envelope metadata. |
| `expo-file-system` | `~57.0.4` | Bounded backup/export file IO | Stream or batch archive work; avoid retaining full plaintext and ciphertext copies simultaneously. |
| `expo-sharing` | `~57.0.12` | User-directed backup and CSV sharing | Keep export explicit and local; no cloud dependency. |

SQLite rules:

- Screens and UI hooks never execute SQL.
- Run migrations, source writes, outbox writes, and FTS maintenance through repository-owned exclusive transactions.
- Enable FTS5 through the `expo-sqlite` config plugin and update relational plus FTS rows atomically.
- TanStack cache, notifications, projections, and recommendations are rebuildable derivatives.
- Jest host tests may prove domain and SQL logic, but a development-test APK must run native SQLite contract tests before PR smoke.

Notification rules:

- Use local notifications only; no Expo Push token or push backend.
- Do not request `SCHEDULE_EXACT_ALARM` by default. Timestamp-derived in-app state remains correct if Android delivers late; add exact-alarm capability only after a phase-specific Android policy review.
- Expo Go is not the verification environment. Use a development build because the app also contains custom native crypto.
- Reconcile on launch, foreground, permission change, and every rest-state transition.

### State and Contracts

| Library | Version | Purpose | When to use |
|---------|---------|---------|-------------|
| `@tanstack/react-query` | `5.101.4` exact | Disposable UI read-model cache | Query-key factories, bounded SQLite reads, and exact invalidation after committed commands/effects. Use React Native `AppState` integration for focus. |
| `zod` | `4.4.3` exact | Runtime boundary validation | Versioned persistence rows, effect payloads, content packs, notification payloads, backup envelopes, restore input, and CSV boundaries. Infer TypeScript types from schemas. |

Do not persist the TanStack Query cache and do not place workout truth in it. Do not optimistically complete a set. Zod belongs at untrusted/persistence boundaries, not inside every pure-domain call or render.

### Backup Crypto

| Technology | Version | Purpose | Why |
|------------|---------|---------|-----|
| Repository-owned local Expo module | App-owned | Argon2id password KDF | Keeps a small, reviewable native surface under CNG and avoids stale React Native wrappers. Run off the JS interaction path. |
| Bouncy Castle `bcprov-jdk18on` | `1.85.2` exact | Android `Argon2BytesGenerator` implementation | Mature native/JVM cryptographic provider with an Argon2id primitive. Pin the Maven coordinate and verify known-answer vectors. |
| `expo-crypto` AES-GCM | `~57.0.1` | Authenticated archive encryption | Already in the Expo compatibility family; no broad Node crypto shim is needed. |

The archive must store a versioned KDF/cipher descriptor, random salt, Argon2id parameters, nonce, ciphertext, and tag. Start with conservative parameters, then calibrate on the minimum Android device to the approved 250–750 ms derivation budget. Lock parameters per archive rather than silently changing old backups. Before shipping restore, prove:

1. RFC/reference Argon2id known-answer vectors.
2. AES-GCM known-answer, wrong-password, and tamper failures.
3. A frozen archive fixture decrypts across app releases.
4. Future iOS implementation produces the same KDF bytes and envelope.
5. Passwords, keys, plaintext, and metric payloads never enter logs.

This crypto choice is **MEDIUM confidence until implemented and measured**. If the local module cannot pass vectors, clean CNG prebuild, and physical-device timing, stop the backup phase and re-research; do not substitute a weaker KDF.

### Testing

| Tool | Version / range | Purpose | Strategy |
|------|-----------------|---------|----------|
| `jest` | `~29.7.0` | Pure domain, application, and host integration tests | Use Expo's resolved version, not Jest 30. |
| `jest-expo` | `~57.0.4` | Expo/RN Jest preset | Must track Expo SDK 57. |
| `@types/jest` | `29.5.14` exact | Jest TypeScript types | Matches Expo's current resolver output. |
| `@testing-library/react-native` | `14.0.1` exact | Component and accessibility behavior | Test semantics and user behavior; avoid implementation-detail assertions. |
| Maestro CLI | `2.8.0` exact | Android lifecycle E2E | PR smoke on API 36; nightly/release coverage on API 24 and API 36 where practical. Requires Java 17+. |

Use three layers:

1. Jest for deterministic rules and application orchestration.
2. Real SQLite contracts, including native Expo SQLite tests in an installed development-test APK.
3. Maestro for permission, background/foreground, process-death, notification, restore, and adaptive/accessibility flows.

Do not add `react-test-renderer` directly; Expo documents it as deprecated for React 19 application tests. Do not treat mocked Expo modules as proof of SQLite, notifications, migrations, or crypto.

CNG policy:

- Commit Expo app configuration, local Expo modules, config plugins, lockfile, scripts, and assertions.
- Ignore generated `android/` and regenerate with `npx expo prebuild --clean --platform android`.
- Never hand-edit generated native files.
- Build with the generated Gradle wrapper, not a globally installed Gradle.
- A native dependency update must pass two consecutive clean prebuilds with no unexplained diff.

## Alternatives Considered

| Category | Recommended | Alternative | Why Not |
|----------|-------------|-------------|---------|
| Framework | Expo SDK 57 CNG | Bare React Native 0.87 | Breaks the reviewed Expo contract and forfeits the SDK compatibility set. |
| Local database | `expo-sqlite` | Realm, WatermelonDB, backend-shaped sync layer | Adds ownership/synchronization machinery the offline single-user app does not need. |
| SQL access | Repository-owned SQL | Heavy ORM as source of truth | Migrations, FTS, exclusive transactions, and rebuildable projections need explicit SQL semantics. |
| UI state | TanStack Query read cache | Redux/Zustand for persisted workout facts | Creates a second truth store and weakens commit-before-acknowledgement. |
| Notifications | Local `expo-notifications` | Push service or background timer loop | Requires network/backend or assumes unreliable JS background execution. |
| AES | Expo Crypto AES-GCM | `crypto-js`, CBC, unauthenticated encryption | Pure-JS/legacy choices do not provide the reviewed native authenticated-encryption path. |
| Argon2id | App-owned Expo module + Bouncy Castle | `react-native-argon2@4.0.0` | Package still contains AGP 4.1 and `react-native:+`; not a boring RN 0.86/CNG dependency. |
| Argon2id | App-owned Expo module + Bouncy Castle | `expo-crypto-argon2@0.0.17` | Pre-1.0, very new, and declares exact npm 10 while this stack uses Node 24's npm 11. Reconsider only after an independent audit. |
| Crypto surface | Narrow KDF module + Expo AES | `react-native-quick-crypto` or Node crypto polyfills | Much broader native/JSI surface than the archive contract requires. |
| Database encryption | Plain local DB plus encrypted exports | SQLCipher | Does not replace portable password-encrypted backups and adds unnecessary native complexity for v1. |
| Unit tests | Jest 29 + `jest-expo` 57 | Jest 30 latest | Expo SDK 57's official resolver selects Jest 29.7; follow the preset family. |
| E2E | Local Maestro CLI | Maestro Cloud as default | Adds an external service and cost to a local-first personal project. |
| Native ownership | CNG-generated `android/` | Committed and hand-maintained native project | Creates drift and undermines clean reproducibility. |

## Installation

```bash
# Scaffold from the reviewed SDK, then retain the generated Expo-compatible versions.
npx create-expo-app@4.0.0 . --template default@sdk-57

# Expo-owned native packages: let Expo choose compatible ranges.
npx expo install expo-router expo-sqlite expo-notifications expo-haptics \
  expo-crypto expo-file-system expo-sharing

# Pure JavaScript application dependencies: exact pins.
npm install --save-exact @tanstack/react-query@5.101.4 zod@4.4.3

# Expo-aligned test stack.
npx expo install --dev jest@29.7.0 jest-expo@57.0.4 \
  @types/jest@29.5.14 @testing-library/react-native@14.0.1

# Compatibility and native generation gates.
npx expo install --check
npx expo prebuild --clean --platform android
```

After scaffolding, remove unused template demo packages and routes rather than carrying the entire default sample into the app.

## Compatibility Checks

Run these on every dependency upgrade:

1. `npm ci` succeeds from a clean checkout.
2. `npx expo install --check` reports no mismatches.
3. Two `expo prebuild --clean --platform android` runs produce the expected generated contract.
4. Generated Gradle/AGP/Kotlin/API/NDK versions match this file or an explicitly reviewed stack update.
5. Debug and release Gradle builds use Temurin 17 and the generated wrapper.
6. Native SQLite tests prove exclusive rollback, WAL/FTS behavior, migrations, and outbox replay.
7. Notification tests cover denied permission, late delivery, foreground reconciliation, undo, and process death.
8. Crypto vectors, frozen archive fixtures, wrong password, tamper, and minimum-device KDF timing pass.
9. Maestro smoke passes on the installed APK before merge.

## What Not to Use

- Expo canary/preview SDKs, React Native 0.87, or independent upgrades outside the SDK 57 compatibility family.
- Global `expo-cli`, global Gradle, floating `latest`, unbounded `*`, or manually edited lockfiles.
- Expo Go as proof for notifications, SQLite native semantics, custom crypto, or release behavior.
- Committed/generated `android/`, direct edits under it, or non-deterministic config plugins.
- Remote push, accounts, cloud sync, Health Connect, or a backend in v1.
- Persisted TanStack caches, optimistic set completion, or UI state as workout truth.
- AsyncStorage/MMKV for authoritative workout facts.
- ORM-generated migrations that hide transaction or FTS behavior.
- `react-test-renderer`, Jest 30, Enzyme, or snapshot-heavy tests.
- Unpinned GitHub Actions, unversioned `curl | bash` in CI, duplicate caches, or signing secrets in artifacts/logs.
- `crypto-js`, AES-CBC, home-grown cryptography, JavaScript/WASM Argon2 on the interaction thread, or a weaker PBKDF silently substituted for Argon2id.
